# Q0 通用操作经验：Panthera / MuJoCo 适配版

来源：XPolicyLab/Q0_Preview，commit `6baccd57ff958570d0db1588370289ee36c8bb70`。这是经过选择和改写的工程约定，不是原 Q0 模型服务或其 RoboDojo 任务策略。当前只完成工具迁移；没有生成或执行轨迹。

## 本任务约定

- 采用当前正式 v1.1 的 Base/M1 小场景、实验室标定的双 Panthera、真实两指接触和桌面。左臂握稳 Base，底脚留在桌面；右臂搬运和插入 M1。
- 控制仍用现有 Panthera/MuJoCo IK、关节力矩 PD 和夹爪执行接口。不得将 Q0 的 X5 配置、25 Hz、归一化夹爪开度、碰撞球或夹爪尺寸混入。
- 用户允许 scripted oracle：可读 simulator ground-truth 物体位姿/接触，并明确标注来源。它不是视觉估计，更不是实物测量。真实抓取/插入仍须经物理完成。
- 只有真实到位后才允许 Virtual Fastening；不能用 attach/weld 替代抓取，不能关闭必要碰撞或直接改物体位姿修正执行失败。

## 姿态与接触工作点

使用 `scripts/q0_geometry.py`：三点只是末端姿态的可读表示，中点为原生 `a_tcp`/`b_tcp`，两点次序定义 TCP 的有符号 +Y，第三点到中点定义 +X。这两个点是虚拟参考点，不是指尖测量值，不控制张口宽度。点顺序反转会真的请求 180° roll，不能以此“修复”IK。

`target_to_tcp()` 输出现有 IK 可消费的 4×4 TCP 目标；`target_from_tcp()` 可从当前实测 TCP 建立参考。平移三个点必须一致；旋转使用世界枢轴和弧度旋转向量。工具没有调用 IK、插值或 simulator stepping。

实际接触区域应由 Panthera 指爪/当前夹持物体的几何确定；`grasp_reference_for` 要求调用者显式给出已测 `working_point_local`。禁止填入上游 X5 的 12.57 mm、145 mm 等默认偏置。当前已验证的是 TCP 数学往返，不是指垫接触区域标定。

## 支撑职责与阶段检查

动作前记录每只手的职责：free / grasping / stabilizing / receiving / releasing。没有运动的手也可能承担支撑，不能把它随意用于拍照或避障回撤。

先确定插入位姿和双方占用空间，再反推抓点、运输路径、撤手位置。可调整 Base 桌面 XY/yaw；只有整条接近、插入和撤手路线都可用，抓法才算合适。端点 IK 成功不代表路径通过。

阶段边界使用同一条动作序列，避免单任务和串联任务另写两套动作。每个阶段输出物体位姿、双臂关节、夹持配置、支撑条件、撤手状态和下一阶段可达性；计划和观测结果分开记。

- Base 夹持：需要两侧接触、桌面支撑、底座漂移/翘起检查。不要照搬上游“抬升 2–3 cm 验证”的默认建议，把 Base 离开桌面。
- M1 抓取：确认接触和物体跟随，再进行搬运。夹爪命令、手指关节位置、估算张口宽度都不能单独证明持有物体。
- 插入前：根据当前 Base 位姿和当前 TCP→M1 实测关系计算目标。任一物体滑移后，旧坐标失效。
- 插入中：保留物理碰撞和摩擦，记录对象相对误差、接触位置/力、夹持状态及支撑漂移；发生阻塞或失握应停止当前段并重新观察。
- 释放前：确认真实到位和后续支撑/紧固条件。未满足到位条件时，不允许执行预先排队的 after-motion release。

Q0 的独立 VLM 检查员只决定 CONTINUE/REPLAN，不修改第二段目标。我们当前先借用这个阶段边界原则，以原生物理证据和人工检查执行；尚未接入 VLM reviewer，也没有可自动放行的 checkpoint executor。

## 空间检查与时间

检查应覆盖双臂、相机外壳、完整指爪、携带零件、桌面及其他接触结构。Q0 的机器人碰撞球不等于完整场景/载荷检查。优先复用 MuJoCo 实际 collider 和已有 swept/FCL 检查；记录离散采样的分辨率，不声称连续证明。

建立接触面的几何约束并不证明存在接触力。上游 0.5–5 mm 平面容差、2 mm inter-arm margin、2 rad/s、3秒/组均不作为本任务的合格阈值。使用已有装配/机器人配置和实际测试确定数值。

区分仿真时间、墙钟时间和控制步数。渲染、思考、API等待不会令物体自动稳定；稳定等待必须真的执行物理步并保持双臂控制。重试需要新的证据或明确改动，不能重复同一失败动作。

## 观察与图像几何

相机图像、内参、当前外参必须来自同一帧；手腕动过后刷新外参。使用原图像素，裁剪必须保留偏移和缩放记录。

迁移的 `camera_ray(K,T,u,v)` / `project_camera(K,T,p)` 显式接收同步标定，T 为 OpenGL camera-to-world（+X右、+Y上、−Z前）。函数拒绝无效刚体变换/内参，不猜测 K。`triangulate` 的低残差不证明像素对应正确，还要检查两相机正深度和重投影。

`q0_inspect.py` 当前只导出原生状态和相机外参，没有拍摄 RGB 或导出同步 K，因此不是完整视觉 observation bridge。不要把它伪装成已完成的感知系统。

## 证据最小集

记录 scene/mesh 版本、observation ID、sim time、命令目标、实测状态、结果和失败原因。只保留仍有效的几何事实和下一步条件，过时坐标标明失效。不能把运动完成、VLM判断或截屏好看当作装配成功。
